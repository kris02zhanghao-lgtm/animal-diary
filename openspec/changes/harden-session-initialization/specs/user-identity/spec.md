## MODIFIED Requirements

### Requirement: 会话就绪前阻塞主界面渲染
系统 SHALL 在 Supabase session 未就绪前阻止主业务页面渲染，并确保初始化请求在有限时间内成功或进入可恢复的失败状态。

#### Scenario: 会话就绪后渲染
- **WHEN** App 挂载时初始化或恢复匿名 session
- **THEN** session 返回前展示加载占位，session 就绪后渲染正常业务页面

#### Scenario: 瞬时连接失败后自动恢复
- **WHEN** 第一次会话初始化明确返回可重试错误
- **THEN** 系统等待短暂间隔后自动重试一次，期间不创建并发初始化流程

#### Scenario: 会话请求超时
- **WHEN** 会话初始化超过配置时限仍未返回
- **THEN** 系统结束加载态且不自动启动可能重叠的底层请求，展示超时原因和“重新连接”操作

#### Scenario: 会话初始化最终失败
- **WHEN** 有限次数的会话初始化均失败或超时
- **THEN** 系统结束加载态，展示连接失败原因和“重新连接”操作，不进入主业务页面

#### Scenario: 用户手动重新连接
- **WHEN** 用户在失败页点击“重新连接”
- **THEN** 系统恢复加载态并重新执行有限次数的会话初始化

#### Scenario: 保留已有匿名身份
- **WHEN** 会话初始化失败、超时或用户手动重试
- **THEN** 系统不得登出、清除 Supabase localStorage 或主动创建替代身份，已有匿名用户的数据归属保持不变
